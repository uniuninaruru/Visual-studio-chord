# Jazz-first engine — 設計・根拠・検証範囲

[日本語](jazz-first-engine.ja.md) | [English](jazz-first-engine.en.md)

状態: 未リリースの大規模エンジン更新。公開サイトへ反映済みという意味ではありません。

## 目的

POP909のポップス注釈から得た出現頻度を、ジャズ全般の正解として扱わないこと。
新規プロジェクトでは、ジャズの和声・旋律・伴奏を一体として設計する決定的な
ブラウザ内エンジンを使います。既存プロジェクトは明示的に切り替えるまで旧経路を
維持します。GPU、Pythonサーバー、コーパスのダウンロードは基本生成に不要です。

「全部入り」は5つの生成プロフィールを同じ編集環境で選べることを意味します。
ジャズ史上の全奏法・全編成を再現済み、プロ奏者と同等、学習済みジャズモデル、という
意味ではありません。対象はまずメロディ、コード／右手、ベース／左手の3トラックです。
ドラム音源やドラマーの対話モデルを実装したことにはしません。

## 設定の契約

プロジェクトの `GeneratorSettings.jazz` は任意のオブジェクトです。

```ts
type JazzSettings = {
  version: 1;
  style: "swing" | "ballad" | "bebop" | "modern" | "neoSoul";
  form: "aaba" | "blues" | "modal" | "free";
  chromaticism: number; // 0..1
  interaction: number;  // 0..1
};
```

- 不在: 旧エンジン。古い保存データへジャズ設定を勝手に足しません。
- 存在: 新しいジャズ経路。`version`、列挙値、数値の有限性と範囲を検証します。
- 初期設定: Swing / AABA、chromaticism 0.35、interaction 0.6。
- Bluesは12小節周期です。12 / 24 / 48小節を使い、8小節を12-bar bluesとは呼びません。
- `chromaticism` は解決を伴う半音接近の傾向、`interaction` は主旋律と伴奏の応答の
  強さです。学習された確率や品質スコアではありません。
- 設定変更だけでは現在の曲を上書きしません。生成操作で初めて新しい設定を使います。

独立セクションは8 / 16 / 24 / 32小節で生成し、生成時のJazzプロフィールを継承します。
任意の順番で結合するため、セクションと結合後のフォームは `free` として保存します。
この経路では旧Pop / Rock等のパーツ別スタイル選択を無効にし、理由を画面に表示します。
パーツごとに5つのJazzプロフィールを直接選ぶ専用UIは、今回の実装範囲には含みません。
Basicで生成方式やJazzプロフィールを変更しても、作成済みパーツは変換されません。
結合対象のパーツと現在の方式・プロフィールが異なる場合は結合を止め、現在の設定で
パーツを再生成するよう案内します。未使用のパーツは結合を妨げません。

## 構成

```text
検証済み設定 + seed + 明示的な進行指定
  → スタイル／フォームと和声の着地点
  → 機能和声のフレーズとボイシング
  → コード音の着地点・接近音・モチーフを持つ旋律
  → 旋律の空間と次のコードを参照する伴奏
  → 共通のトラック定義
      → ピアノロール
      → Web Audio再生
      → マルチトラックMIDI
```

基本方針は、各トラックを無関係な乱数列として生成して最後に重ねるのではなく、
和声の到達点と時間構造を共有することです。メロディ側の非コード音はそれだけで
誤りと判定しません。接近からどこへ解決するか、拍上の役割を区別します。
低音はコード構成音の単純巡回だけにせず、次の和音への進行を参照します。

スウィング、バラード、ビバップ、モダン、ネオソウルは、それぞれ異なる密度、
休符、半音接近、和声語彙、伴奏リズムを持つ作成者定義のプロフィールです。
名前だけを変更したプリセットでも、POP909の頻度をジャズの頻度と言い換えたものでも
ありません。一方、パラメータはジャズ音源から推定した重みではありません。

整数tick（PPQ 480）を保存の基準とし、ピアノのMIDI 21–108の範囲を守ります。
旋律のタイミング補正は保存するノートに一度だけ反映し、伴奏の補正は共通トラック経路で
行います。旧grooveと二重に適用しないことを実装・テストの要件とします。
音声用だけに隠れた別の音符列を作りません。

## POP909を外す境界

新しい生成、通常のブラウザ順位付け、セクション自動接続は、POP909スナップショットを
暗黙に読み込みません。ジャズの実測コーパスがない場合、表示するのは理論に基づく候補と
その理由です。未観測の頻度や尤度を作って表示しません。

バックエンドも、モデルファイルが存在するだけで `auto` からPOP909へ切り替えません。
旧研究の再現スクリプト、テスト用fixture、明示的なcorpus providerは互換用に残せますが、
それらは新しい標準経路とは分離します。ユーザーが置いたデータや重みは削除しません。
過去のPOP909 / McGill評価を、このエンジンの評価結果として再利用しません。

特にスウィング論文は、ソリストと伴奏の相対タイミングを扱います。このアプリの
プロフィール定数を論文からフィットしたわけではなく、記載の結果がこの合成音源での
聴感向上を証明するわけでもありません。

## 検証と残る課題

2026-09-11の開発ブランチ検証では、フロントエンド1,460テスト、型検査、Lint、
製品ビルド、バックエンド187テスト、環境診断8テストが成功しました。
生成・トラック境界の追加検査は5,400条件で成功し、6組のMIDI／JSONを再読込検証しました。
一方、ブラウザE2EはChromium 8/8、WebKit 5/8で、WebKitの連続生成・セクション操作で
ページクラッシュが残っています。変更前HEADではセクション操作が成功するため、
この更新の回帰として調査中です。Safari対応完了・リリース可能とは扱いません。
ネイティブログはJavaScriptCore DFG JITの `VirtualRegisterAllocationPhase::run()` 内での
`EXC_BREAKPOINT / SIGTRAP` を示しています。表示用Jazzトラック経路を外しても再現しました。
引き金となる最小の処理は未特定で、ブラウザ判定による機能停止・テストのskip・
JIT無効化を製品側の修正として採用していません。診断用変更は残していません。
Windows/Linux実機、実GPU、プロ奏者による聴感評価はこの結果に含みません。

機械検証では、seed再現性、12小節周期、tick境界、音域、ロック済み小節、範囲再生成、
保存復元、トラック間整合、MIDI出力、サーバーなしのUI操作を確認します。
「非コード音率が低い」「テストが通る」だけでは、音楽が良くなったとは結論しません。

聴感比較では、同じキー、BPM、小節数、音源、音量、再生範囲を使い、スタイルの違いと
品質の違いを分けて判断します。最初はコードのみ、旋律のみ、低音のみ、全トラックの
順に確認します。プロ奏者による評価、盲検比較、実演奏への適合度は別途必要です。

今後の学習モデルは、この理論エンジンと比較できるベースライン、用途に合うジャズ資料、
学習・評価の分離、能力を正しく宣言したmanifestを持つ必要があります。旧POP909重みの
ラベルだけを変えることはしません。

## 手元で比較用MIDIを作る

依存関係のセットアップ後、プロジェクトのフォルダで実行します。

```sh
node scripts/compare-jazz-generation.mjs
# 出力先とseedを指定する場合
node scripts/compare-jazz-generation.mjs ./artifacts/jazz-generation-comparison jazz-review-1
```

5プロフィールと12小節ブルースの合計6組のMIDI／編集用JSON、検証結果とハッシュを
含む`comparison.json`を作ります。JSONの再読込と、MIDIを再解析したノート列が
共通トラック定義と一致することを確認します。キーはC、BPMは120で共通ですが、
ModernはModal、Neo SoulはFree、Bluesは12小節なので、スタイルだけを変えた厳密な
A/B実験ではありません。DAWでは同じトラック音源と音量を割り当てて聴いてください。

MIDI自体にピアノ音源や完成したミックスは含まれません。数値は生成・書き出しの
検証記録で、聴感の優劣を自動採点したものではありません。

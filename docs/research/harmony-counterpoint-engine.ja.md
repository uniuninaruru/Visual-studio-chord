# 和声法・対位法を中心にした生成エンジン v2 設計

状態: 実装設計。資料台帳は [harmony-counterpoint-sources.ja.md](harmony-counterpoint-sources.ja.md)。この設計はジャズを標準とする新規生成を対象とする。旧プロジェクトの音符と和音は読み込み時に再生成しない。

## 置き換える問題

現行の新規生成は `jazzHarmony.ts` が小節ごとのコードを決め、`jazzMelody.ts` が確定済みの和音の上に旋律を置き、`jazzArrangement.ts` が低音と伴奏を付ける。任意の対旋律は `counterpoint.ts` でさらに後から書く。この順序では、和音遷移・旋律・低音・対旋律の相互作用を計画できない。`findCounterpointIssues` も同時刻の発音だけを比較するため、保持音とコード変更の衝突を見逃す。

新規作成には明示的な `jazz.version: 2` を使い、`version: 1` の保存済み設定の再生成は旧経路で継続する。v2 は既存 `GeneratedComposition` の `ppq=480`、整数tick、21–108 MIDI、コード／旋律／声部／セクション／ロック、共有トラック、MIDI・JSON出力を守る。モデル・ネットワーク・GPUは不要。

## 生成順と共通の評価対象

```text
設定とセクション
  → フレーズの終止・緊張曲線・転調目標
  → 和声機能の経路とコード候補（明示進行は拘束条件）
  → 低音＋内声のガイドトーン＋旋律の構造音を同じ境界で探索
  → リズム、対旋律、経過音・隣接音・掛留を追加
  → 全トラックの実発音をtickで再評価
  → GeneratedComposition／DAWトラック／説明可能な診断
```

探索状態は「現在の和声、前の和声、低音、内声2本、主旋律、対旋律、フレーズ内位置」を持つ。和音だけを個別に最適化しない。決定的なシードから候補順を定め、候補数の上限・ビーム幅を設定で制御できるようにする。音符を秒単位で保存しない。

| 規則 | 厳格な種対位法 | 共通慣習和声 | ジャズ／ブルース／モーダル |
| --- | --- | --- | --- |
| 音域・時刻・声部の識別 | 必須 | 必須 | 必須 |
| 意図しない声部交差 | 禁止 | 強い減点 | 左右の役割を踏まえ減点 |
| 強拍の和声音 | 原則必須 | 強く優先 | 3度・7度と明示テンションを優先 |
| 平行5度／8度 | 禁止 | 強い減点 | 独立した2声なら減点。意図した平行ボイシングは許容 |
| 弱拍の不協和 | 第2種は順次経過音、第3種は条件付き隣接音 | 前後関係で許可 | 経過・接近・エンクロージャ・明示テンションを許可 |
| 掛留 | 協和準備→保持→順次解決を必須 | 同じ文法を優先 | 様式に応じ、意図的な遅延解決を許す |
| 終止 | 定めた終止型を検証 | フレーズ末尾を検証 | ii–V–I、代理、ブルース／モードの別終止も扱う |

ここで「和声音」は音階所属ではなく、実際のコード記号（sus、6、9、変化音を含む）から決める。第1種の協和判定をジャズのテンションに適用しない。引用元は資料台帳の `CP-1/2/3/4`, `H-FORM`, `J-GUIDE`, `J-BLUES`, `J-MELODY`。

## モジュール境界

1. `theoryRules`: コード記号から音集合、拍の強弱、2声の相対運動、並行完全音程、非和声音の前後関係を評価する純粋関数。診断は規則ID・tick・声部・重大度・理由を返す。
2. `theoryHarmony`: セクション終止を先に決め、T→PD→D→Tなどの候補経路をビーム探索する。ブルースのI7／IV7、モーダルな停滞、明示的な進行は別の文法とし、コード名の並びだけで終止や転調を名乗らない。
3. `theoryVoices`: 低音、コード内声、旋律、オプションの対旋律の構造音を同じ和声境界で候補評価する。滑らかな3度・7度連結、反行／斜行、音域、フレーズ輪郭、跳躍後の回復をスコアに含める。
4. `theoryOrnaments`: 構造音の間へ音価と経過・隣接・接近・掛留を配置する。各非和声音は種類に応じた前後関係が成立したときだけ正式データにする。
5. `theoryEngine`: `generator.ts` の共通入口と `regenerateRange` から v2 を呼び、既存の `GeneratedComposition` に変換する。`compositionTracks.ts` の共通トラックを音の真実とし、再生と出力を別実装にしない。

`version: 1` と v2 を同じシードで同じ結果だと誤認させない。既存ファイルでは読み込んだ音符を優先する。v2 の部分再生成ではロック済み小節と選択範囲外のイベントを保持し、保持した和声を最終の旋律／声部探索へ渡す。探索不能なら候補を破棄し、元の曲と診断を返す。

## 画面と検証

- Basicには「和声と声部から生成」とスタイルを表示。Advancedに厳格度、対旋律の独立度、候補数を置く。各規則の名前・音楽的意味・次に取れる操作を日本語／英語で示す。
- トラックごとに低音・和音・旋律・対旋律を見せ、問題のtickを選択できるようにする。生成中も再生・編集を止めず、結果は採用前プレビューとする。
- 主要ゲート: seed再現性、12小節ブルース、明示進行、短調ii–V–i、3/4・4/4・6/8、全鍵、88鍵範囲、強拍／弱拍／掛留の正例と反例、音が伸びた状態での和音変更、声部交差と平行、ロック付き部分再生成、MIDI／JSON再読込。
- 定量値は「正しい音楽」の証明にしない。同じ音色・音量・BPMで旧エンジンとv2を盲検比較し、和声接続、声部独立、旋律の自然さを別々に評価する。結果が悪ければ係数を調整する前に失敗の規則と音例を記録する。

実装は資料台帳の順に進める。v2 の全ゲートと実聴比較が済むまで、完成や音質向上を宣言しない。

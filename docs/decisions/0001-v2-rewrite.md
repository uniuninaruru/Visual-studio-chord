# 0001 v2 を一から作り直す

状態: 採用（2026-11-19）

## 背景

v1 の見直しで次のことが分かった。

- 生成パイプラインが3本（legacy、jazz v1、jazz v2）あり、起動時の既定はジャズ経路だった。
  ジャズ経路はボイシング選択・セクション接続・テンション・旋律骨格のどれも使っておらず、
  それまでの改善は最初に聴く音に届いていなかった。
- 進行を作る入口が5つ、オプトイン設定が24個あった。「実装したが既定でオフ」「別の経路には
  配線されていない」が何度も起きたのは、この構造のせいだった。
- 「良くなったか」を決める正解データがなく、指標は何度も間違っていた。
- main の CI は、`ubuntu-latest` の更新で固定していた Python が消えて3週間赤のままだった。
  1回の push で13ジョブが走り、赤が意味を持たなくなっていた。
- リポジトリは iCloud 同期下にあり、`.git/refs` に重複 ref が作られて `git fetch` が壊れ、
  ローカルのテストは読み込みの停滞で42分かかっていた（iCloud の外では40秒）。

## 決定

1. **コードは全部捨て、資産だけ引き継ぐ。** v1 は `v1-final` タグに残し、公開サイトは
   v2 が受け入れ一覧を満たすまで v1 のまま。作業は `rewrite` ブランチで行う。
   引き継ぐのは POP909 の n-gram モデル（`models/`）、その学習スクリプト（`tools/corpus/`）、
   調査文書と出典台帳（`docs/research/`）、評価用の固定ケースと v1 の音（`eval/`）。
2. **バックエンド、ニューラル、Docker、CUDA/MPS、LAN 起動は v2 に入れない。**
   ニューラルは v1 でも「909曲に対してモデルが大きすぎる」として停止していた。
   再開するときはブラウザ内で推論する別モジュールとして戻す。
3. **生成パイプラインは1本。** 構成 → 和声 → 旋律 → ボイシング → 演奏。スタイルは
   コードの分岐ではなくデータ（コーパス、ボイシング表、リズム表）で表す。
   メロディ MIDI からの和声付けは、和声探索に「メロディとの適合」の項を足すだけにする。
4. **機能フラグを作らない。** 全段階が常に動く。ユーザー設定は8個以下
   （キー、モード、テンポ、拍子、長さ・構成、スタイル、複雑さ、シード）。
5. **保存するのは生成結果。** シードからの再現は同じメジャー版の中だけ保証する。
   互換のために古いエンジンを残さない。
6. **「良くなった」は耳で決める。** `eval/cases.json` の12ケースを、前の版とブラインドで
   聴き比べ（`/listen/`）、勝つか引き分けない限り既定にしない。数値は不変条件
   （音域、長さ、重なり）の確認にだけ使う。
7. **音楽コアは UI から独立させる。** `packages/core` は React・Tone.js・DOM を import
   できない（ESLint で強制）。1ファイル400行まで。
8. **CI は PR と main だけ、3ジョブ。** runner とツールのバージョンは固定する。
9. **既定のスタイルはデータのあるポップ系。** ジャズは規則ベースのプロフィールとして入れ、
   ジャズのコーパスが入るまで「学習済み」とは名乗らない。（ユーザー確認待ちの仮決定）

## 段階と完了条件

利用者への確認（2026-11-19）で、主な使い手は DAW を使う作曲者、一番多い使い方は
「次のコードを探す」、譲らない点は「理由を説明できる生成」と決まった（`PRODUCT.md`）。
そこで、曲全体の生成より先に「次のコード」候補とその画面を作る。

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 0 土台 | クローン移動、v1 の保全、CI、試聴ハーネス、v1 の基準音 | ハーネスで v1 が聴ける（済） |
| 1 和声の土台と「次のコード」 | 調に合った綴り、n-gram による候補、理論による理由づけ | McGill-Billboard で実際の次の和音が上位に入る率を v1 の候補と比べて上回る。候補の理由がすべての候補に付く |
| 2 進行ビルダー画面 | 進行を1つずつ組み立てる画面。候補を前後の流れと一緒に試聴、MIDI 書き出し | e2e（chromium、webkit）と、作曲者本人が実際に1曲分の進行を組めること |
| 3 曲全体の生成 | 同じモデルで曲全体を探索、セクションの役割、終止の制約 | A/B で v1 に過半数で勝つ |
| 4 ボイシング | 曲全体を動的計画法で選ぶ | A/B で前の版に勝つか引き分け |
| 5 旋律と MIDI 取り込み | 骨格音から装飾音、取り込みは同じ和声探索 | A/B と取り込みの e2e |
| 6 切り替え | v1 プロジェクトはイベントだけ取り込む、README、Pages | v2 を公開 |

## v1 で見つかっていて、繰り返さないもの

- 調に合わない和音の綴り（E♭メジャーで「G#(13)」「D#」「A#(9,13)」）。
- 既定でオフのまま「完了」とした機能。
- 指標の検証不足（存在しないフィールドを読んで「100% 同一」と出した等）。

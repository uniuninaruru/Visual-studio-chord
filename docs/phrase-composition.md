# フレーズ主導の生成

Basicの「作曲方式」で「フレーズ主導」を選び、生成する。新規プロジェクトの初期値はこの方式。以前のJSONや保存済みプロジェクトは従来の方式を維持するため、切り替えは明示的に行う。

## 生成するもの

- セクションの種類ごとに短いリズムと音程の輪郭を作り、サビの再登場時にも使う。落ちサビ・大サビは同じ主題を異なる音域で演奏する。通作形式ではセクションごとに素材を作る。
- フレーズ設計が有効なら、提示・応答・断片化・終止の役割に沿って展開する。着地の長い音と息継ぎの休符を先に確保する。
- 複数の音列候補をフレーズ単位で探索し、主題の輪郭、実際の和音、順次進行、跳躍後の動き、非和声音の準備と解決を評価する。
- ジャンルごとの進行候補とベースのリズムを使う。自動選択した進行の未指定の和音には、設定に応じてセブンスやテンションを加える。明示的に選んだ進行の指定は維持する。
- ベースと伴奏にも同じグルーヴを適用する。複音は音高別に処理し、同時発音が1 tickに潰れることを防ぐ。左手シェルの指定は維持する。

「フックのまとまり」を上げると輪郭を保持し、下げると変形や骨格の影響を強める。これらは作曲上の設計とヒューリスティックであり、聴取評価から学習した品質スコアではない。音源・ミックスを含む完成音源を生成するモデルでもない。

## 再生・編集・保存

再生とMIDIは同じ演奏トラックを使い、強弱・タイミング・音の長さを保持する。追加声部の二重発音、微小なグルーヴを25 msに引き延ばす問題、MIDIで伴奏の強弱を固定値にする問題を修正した。明示的なMIDIベロシティ上書きAPIは利用できる。

和声診断は、ボイシングで省略されたルートや5度も和音の定義に含めて扱う。たとえばAm7の伴奏でEを省略していても、メロディのEを説明不能な非和声音と誤判定しない。対旋律・カノンはメロディの演奏タイミングを引き継ぐため、グルーヴを二重適用しない。

ノート移動・削除・クオンタイズ・貼り付けは、編集元と編集先のロックを確認する。複数選択にロック対象が含まれる場合は操作全体を適用しない。コピーはノートIDではなく内容を保存し、元ノートを削除した後にも貼り付けられる。

IndexedDBは個々のリクエスト成功時ではなくトランザクションの`complete`で保存成功とする。これは[MDNのトランザクション完了イベントの定義](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event)に基づく。コミット失敗時は代替保存に進み、最新のメモリ上の編集を古い保存内容より優先する。

## 比較と検証

```sh
npm ci
node scripts/compare-phrase-generation.mjs artifacts/phrase-comparison
npm --prefix frontend run test -- --maxWorkers=4
npm run typecheck
npm run lint
npm run build
```

比較スクリプトはJ-pop・lo-fi・EDM・jazzのMIDIとJSONを旧方式・新方式で生成する。ペア内のシード、キー、テンポ、小節数は同じ。どちらも修正後のMIDI書き出しを使う。生成物はGitへ含めず、同じ音源を使ってDAWで比較する。

`music.phraseComposer.test.ts`は主題の再登場、終止と休符、ジャンル差、拍子と音域、再現性、旧エンジンの固定ハッシュを検証する。`export.performance.test.ts`は演奏トラックとMIDIをノート単位で比較する。音価抽選・左手クリアランス・伴奏の音域オフセットの旧数値校正テストは旧エンジンを明示して保持し、新方式の主題・音域・強弱は独立して検証する。

テスト通過はデータや機能の検証であり、「以前より音楽的に良い」という証明にはならない。実際の試聴による評価は別に必要。
